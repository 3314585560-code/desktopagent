## 什么时候用

用户想审查当前工作区的实际改动。审查以读为限，报告能定位的缺陷和风险。

## 步骤

1. 用户给了文件或目录时，只审查该路径。范围不明确时，收集当前工作区的已暂存和未暂存差异。
2. 调用现有 bash 工具。command 填 skill-script；审查指定路径时填 skill-script 加一个空格和工作区相对路径。整段路径按单个参数传给 scripts/collect_diff.py，空格保留。建议 timeout 为 25 秒。
3. 用脚本返回的 status、unstaged、staged 确认范围。未跟踪文件只在状态中显示，需要另外用 read 查看对应文件；返回内容有截断时，按具体路径再次取差异或查原文件。
4. 对照改动前后验证输入、失败路径与调用者。问题按影响排序，给出文件和位置、触发条件和影响。没有确定证据的猜测标成待核实。
5. 如果 Git 不可用、目录没有仓库、或者终端权限未开启，准确报告原因。可以请用户贴出 diff，继续做只读审查。禁止顺手编辑、暂存、提交或推送。

## 怎么算做完了

明确审查范围、实质发现和未验证项。每条发现能对应实际差异或文件证据。
