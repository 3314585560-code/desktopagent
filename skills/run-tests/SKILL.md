## 什么时候用

用户想知道代码是否通过测试，或希望解释一次失败。任务以运行和报告为限，修改代码需要用户另外授权。

## 步骤

1. 先读取项目说明或测试配置，找出实际测试入口。项目使用 pytest 时优先使用 python -m pytest -q；标准库测试使用 python -m unittest discover。用户点名某个文件或用例时，只跑对应范围。
2. 通过现有 bash 工具执行项目自己的命令，并设置合理超时。终端未授权时说明需要开启「允许终端命令」。缺少依赖或没有找到测试入口时，给出缺少的具体信息，不能把无法运行当作全部通过。
3. 记录真实退出码、通过和失败数量。失败时最多摘出三条最相关的报错，逐项报告用例、期望、实际和最可能的原因。区分断言失败、导入失败、超时和测试发现数量为零。
4. 若失败可能由工作目录或命令错误造成，先核对项目说明，修正命令后再试一次。用第二次真实结果替代第一次的错误判断，并交代重试原因。
5. 维持只读报告范围。需要改代码或安装依赖时，列出最小的下一步建议供用户决定。

## 怎么算做完了

给出实际测试命令、退出状态和用例数量。对失败说明原因或待核实项，对未能运行交代阻碍。
